# 机器人运动学标定部署与实施流程

本文档给出 `robotkinecal` 从环境部署、前期准备、仿真验证、真实数据采集，到标定结果验证和上线的完整流程。

## 1. 适用范围与当前限制

`robotkinecal` 适用于仅包含旋转关节的串联运动链，支持：

- Robotics Toolbox 的 `ERobot`、`DHRobot` 和 `PoERobot`；
- 完整 `SE(3)` 末端位姿观测；
- 仅三维末端位置观测；
- POE 螺旋轴输出；
- `ERobot`/`DHRobot` 的 URDF XYZ/RPY 输出。

对于人形机器人，当前应把整机拆分成多条串联链分别标定，例如：

```text
pelvis → torso → left arm → left hand
pelvis → torso → right arm → right hand
pelvis → torso → head
pelvis → left leg → left foot
pelvis → right leg → right foot
```

当前版本尚不支持一次性联合标定共享躯干参数、浮动基座、多末端约束、相机外参或机械柔性。

## 2. 总体实施流程

```text
明确标定对象和精度目标
        ↓
建立坐标系、单位和变换方向规范
        ↓
部署软件环境并运行测试
        ↓
使用仿真数据验证完整数据链
        ↓
标定相机内参及固定外参
        ↓
规划具有良好可观测性的机器人姿态
        ↓
同步采集关节角和末端观测
        ↓
清洗数据并划分标定集/验证集
        ↓
运行运动学标定和可观测性检查
        ↓
在独立验证集上比较标定前后误差
        ↓
导出 POE/URDF 参数
        ↓
仿真回归、低速实机验证、分阶段上线
        ↓
保留名义模型和一键回滚能力
```

## 3. 软件部署

### 3.1 创建 Conda 环境

推荐使用 Python 3.10～3.12。当前开发环境使用 Python 3.10：

```bash
conda create -n robotkinecal python=3.10
conda activate robotkinecal
```

### 3.2 安装项目

普通使用：

```bash
python -m pip install -e .
```

开发、测试和构建：

```bash
python -m pip install -e ".[dev]"
```

### 3.3 验证环境

```bash
ruff check .
pytest -q -W error
python -m build
python Examples/MinimalExample.py
```

预期结果：

- Ruff 无错误；
- 全部测试通过且没有警告；
- wheel 和源码包构建成功；
- Minimal Example 正常收敛并输出 POE、零位末端姿态和 URDF 参数。

## 4. 前期准备

### 4.1 明确标定目标

开始采集前应明确：

- 标定哪一条串联运动链；
- 目标末端 link 名称；
- 是使用完整位姿还是仅位置观测；
- 期望改善的位置与姿态精度；
- 使用场景的负载、温度、支撑方式和工作空间；
- 最终使用 POE 模型还是回写 URDF；
- 哪些参数允许修改，哪些参数必须固定。

建议先从单臂或单腿开始，不要直接对整个人形机器人进行无约束全身优化。

### 4.2 固定坐标系约定

建议统一采用：

```text
A_T_B：坐标系 B 在坐标系 A 中的位姿
长度单位：m
关节角：rad
姿态误差：rad
```

当前库要求末端观测为：

```text
Base_T_EE
```

如果测量系统观测的是刚性安装在末端的 Board/Marker/Tracker，则可以直接标定到该目标坐标系：

```text
Base_T_Target = Base_T_EE · EE_T_Target
```

固定的 `EE_T_Target` 会主要被末端零位姿态吸收，关节轴理论上保持一致。可运行以下回归示例验证：

```bash
python Examples/FixedTargetFrameComparison.py
```

但此时求解结果的末端语义是 Target，而不是原 `ee_name`。若需要输出原机器人末端的 URDF 参数，必须先移除已知的 `EE_T_Target`；否则应在 URDF 中将 Target 建成显式固定子 link，不能把目标安装偏移写入原末端 link。

不要混用：

```text
Base_T_EE 与 EE_T_Base
Camera_T_Target 与 Target_T_Camera
mm 与 m
degree 与 radian
```

### 4.3 选择测量方案

优先级建议：

```text
激光跟踪仪
> 多相机光学动捕
> 固定工业相机/双目相机
> 单台 RGB-D 相机
> 机器人头部相机自观测
```

眼在手外、标定板安装在末端时：

```text
Base_T_EE
= Base_T_Camera
  · Camera_T_Board
  · inverse(EE_T_Board)
```

当前仓库不能分别联合估计 `Base_T_Camera` 或 `EE_T_Board`。是否必须提前获得它们取决于输出目标：

- 复合目标模式：只需要 `q → Camera_T_Target`，可直接输入 `Camera_T_Target`，不需要预先手眼标定；结果表达在 Camera 坐标系并终止于 Target；
- 机器人本体模式：需要 Base/EE 物理参数或回写原 URDF，必须提前获得外参并把观测转换为 `Base_T_EE`。

眼在手上、相机安装在末端时：

```text
Base_T_EE
= Base_T_Board
  · Board_T_Camera
  · inverse(EE_T_Camera)
```

变换方向应根据视觉系统实际返回值调整，不能只按变量名称猜测。

### 4.4 标定测量系统

这些准备项是否必需，取决于期望输出，不能一概要求全部完成。

**仓库求解的必要条件：**

- 每个关节配置 `qᵢ` 都有一个同步的完整位姿或位置观测；
- 所有观测使用一致的坐标系、变换方向和单位；
- 数据批次内 Camera、Board/Target 与其安装主体之间的固定关系不发生变化。

**由图像自行计算 Target 位姿时通常需要：**

- 相机内参和畸变参数；
- 正确的标定板几何尺寸；
- 足以满足项目精度的 Target 检测和 PnP 质量。

如果上游测量系统已经直接提供可靠的 SE(3) 位姿，本仓库本身不要求重新执行相机内参或畸变标定，但仍应确认其坐标定义、单位和质量指标。

**仅在输出机器人本体 `Base_T_EE(q)` 并准备更新原始 URDF 时需要：**

- 已知或另行标定 `Base_T_Camera`（也可通过等价的 `Base_T_Board` 坐标链获得）；
- 已知或另行标定 `EE_T_Board`、`EE_T_Target` 或 `EE_T_Camera`；
- 使用这些固定外参把视觉观测转换到 `Base_T_EE`。

如果目标只是标定复合映射 `q → Camera_T_Target`，上述 Base–Camera 和 EE–Target 外参不是求解前置条件；但输出参数属于 Camera/Target 复合模型，不能直接写回机器人原始 URDF。

**推荐但非求解器强制要求的质量检查：**

- 时间同步检查；
- 位姿检测静态重复性测试；
- 外参和安装刚性的复查；
- 独立验证集测试。

静态重复性测试不要求固定采集 100 帧。快速检查可使用 20～30 帧，常规建议使用 30～50 帧；正式验收或需要分析时间抖动时可采集 50～100 帧，或覆盖 5～10 秒。连续帧可能具有相关性，因此采样时长和有效独立样本比恰好达到 100 帧更重要。如果静态重复性已经接近或超过目标精度，应先改善测量系统，再增加运动学标定姿态。

### 4.5 安全准备

- 规划姿态必须通过碰撞检查和关节限位检查；
- 首次执行采用低速度、低加速度；
- 设置急停和软件停止条件；
- 标定板、相机和标记必须刚性安装；
- 检查线缆不会在大范围运动中拉扯末端；
- 人形机器人单脚支撑采集应有防跌倒保护；
- 保存并版本化原始 URDF，禁止直接覆盖唯一副本。

## 5. 数据格式与目录建议

每条有效观测至少保存：

```text
sample_id
joint_timestamp
measurement_timestamp
joint_positions
Base_T_EE 或原始 Camera_T_Board
视觉重投影误差/动捕质量指标
机器人状态
支撑状态
负载和温度（如可用）
```

建议目录：

```text
dataset/
├── metadata.yaml
├── camera_intrinsics.yaml
├── extrinsics.yaml
├── raw/
│   ├── images/
│   ├── joint_states.csv
│   └── detections.csv
├── processed/
│   ├── calibration_poses.npz
│   ├── train_indices.txt
│   └── validation_indices.txt
└── logs/
```

不要只保存转换后的末端位姿。应保留原始图像、角点、重投影误差和原始外参，以便重新处理和追溯问题。

## 6. 姿态规划与数据量

### 6.1 推荐数据量

样本数不是仓库的固定要求。对于 `n` 个旋转关节，当前参数化包含：

- 完整 6D 位姿观测：`4n + 6` 个参数，每个姿态最多提供 6 个约束，计数意义下的理论下限为 `ceil((4n + 6) / 6)`；
- 仅位置观测：`4n + 3` 个参数，每个姿态最多提供 3 个约束，计数意义下的理论下限为 `ceil((4n + 3) / 3)`。

因此 7 自由度机械臂的计数下限分别是 6 和 11 个姿态。但这只是方程数量下限，不保证回归矩阵满秩，也不抵抗噪声、离群点和系统误差，不能作为实机正式标定数量。

对 6～7 自由度单臂，完整 6D 位姿观测可按测量质量选择：

| 场景 | 建议标定数量 | 独立验证数量 |
|---|---:|---:|
| 无噪声仿真/公式检查 | 8～15 | 5～10 |
| 算法与接口调试 | 10～20 | 5～10 |
| 高质量动捕、激光跟踪仪 | 20～40 | 10～20 |
| 稳定的工业视觉或多相机系统 | 30～60 | 15～30 |
| 常规 AprilTag、棋盘格视觉 | 50～100 | 15～30 |
| 高噪声、遮挡或边缘视场明显 | 80～150 | 20～40 |

仅位置观测的约束更少：仿真可从 15～25 个开始，高质量测量通常 30～60 个，常规视觉通常 60～120 个，高噪声场景可使用 100～200 个；同时确保测量点不位于最后一个旋转关节轴线上。

双臂、人形机器人应按独立运动链分别评估，不应简单把所有关节和样本合并成一个总数。每条 6～7 自由度链可从上表范围起步；共享躯干关节则需要在不同支撑状态和双侧任务中共同激励。

数量不是唯一指标。100 个高度相似的姿态可能不如 40 个经过可观测性设计的姿态。

推荐采用增量采集：先采 20～30 个高质量完整位姿，预求解并检查满秩、条件数和独立验证误差；随后每次增加约 10～20 个互补姿态。当新增数据不再明显降低验证误差和参数波动时停止。条件数只用于同一参数化和缩放下的相对比较；经验上 `< 100` 通常良好，`100～1000` 需谨慎，`> 1000` 应优先检查姿态退化和尺度设置，而不是机械套用绝对阈值。

### 6.2 样本少时会发生什么

样本不足不只意味着“精度低”，还可能意味着“问题不可解”。应区分以下情况：

| 数据状态 | 典型表现 | 结论 |
|---|---|---|
| 低于方程计数下限 | 方程数少于待估参数数 | 必然无法唯一辨识全部参数 |
| 数量足够但姿态退化 | 回归矩阵秩亏，部分奇异值接近零 | 仍然不可辨识；继续重复相似姿态无效 |
| 刚好满秩、冗余很少 | 能收敛，但条件数偏大，换一帧或换一批数据时参数明显变化 | 数学上可解，工程上不稳定 |
| 姿态充分且具有合理冗余 | 满秩、条件数稳定、独立验证误差较低 | 可进入工程验收 |

当噪声近似独立且无明显系统偏差时，增加有效样本会降低参数方差，随机误差通常近似按 `1 / sqrt(N)` 下降。例如从 25 个有效样本增加到 100 个，随机误差理想情况下约减半，而不是降至四分之一。该规律不适用于强相关连续帧、重复姿态或系统误差：

- 100 个高度相似的姿态可能不如 40 个覆盖充分的姿态；
- 同一静止姿态的连续图像用于估计该姿态的测量均值和重复性，不等价于 100 个运动学标定姿态；
- 固定外参偏差、标定板尺寸错误、时间不同步和结构变形不会靠增加样本自动消失；
- 标定集残差很小不代表泛化良好，必须检查未参与求解的验证集。

因此停止采集不能只看 `solve()` 是否返回收敛。至少应同时满足：回归矩阵满列秩、条件数可接受、不同数据子集的标定参数稳定、独立验证误差达到目标，并且继续增采后的收益已经趋于饱和。

### 6.3 姿态覆盖原则

- 每个待标定关节都应有明显的正负方向变化；
- 不要让相邻关节始终同步运动；
- 覆盖工作空间近、中、远距离；
- 覆盖多个末端方向和标定板法向；
- 避免所有样本位于同一平面或狭小区域；
- 避免奇异位形及关节极限附近姿态；
- 覆盖实际任务使用的负载和支撑状态；
- 眼在手外时考虑相机视野、遮挡、景深和图像边缘畸变。

### 6.4 数据集划分

在求解前固定划分：

```text
70%～80%：标定集
20%～30%：验证集
```

验证集应覆盖标定集没有完全重复的姿态和工作空间区域。禁止根据验证结果反复挑选同一验证集中的样本后仍将其称为独立验证集。

## 7. 仿真验证流程

仿真验证的目标不是证明真实机器人一定有效，而是验证模型、坐标系、数据格式和求解器构成的完整闭环。

### 7.1 运行仓库基准示例

```bash
conda activate robotkinecal
python Examples/MinimalExample.py
```

检查：

- `termination_reason == "converged"`；
- 回归矩阵满秩；
- 条件数没有异常增大；
- 每轮更新后误差不高于更新前误差；
- 标定后误差显著低于名义模型；
- 螺旋轴方向范数接近 1；
- 零位末端旋转矩阵满足 `R.T @ R ≈ I`、`det(R) ≈ 1`。

### 7.2 建立目标机器人仿真模型

1. 从实际使用的 URDF 加载名义模型；
2. 确认关节顺序、方向、零位和末端 link；
3. 对关节轴位置、方向和末端零位施加已知小扰动；
4. 从扰动后的“真值模型”生成观测；
5. 给观测加入符合测量系统的噪声；
6. 使用名义模型启动标定；
7. 比较估计参数与已知扰动；
8. 使用未参与求解的姿态验证末端误差。

建议至少测试：

```text
无噪声完整位姿
有噪声完整位姿
仅位置观测
观测数量不足
姿态分布单一
少量离群点
错误坐标系方向
错误长度/角度单位
```

### 7.3 仿真验收标准

不建议使用单一固定阈值，至少应满足：

- 无噪声数据能够收敛到数值精度附近；
- 有噪声数据的验证集误差明显优于名义模型；
- 标定参数修正与注入扰动的数量级一致；
- 增加姿态多样性后条件数改善；
- 减少数据或制造退化姿态时，秩和条件数能正确暴露问题；
- 相同数据和配置重复运行得到一致结果。

### 7.4 生成仿真标定报告

```bash
python Examples/GenerateCalibrationReport.py
```

默认生成：

```text
reports/minimal_example/
├── minimal_example_calibration_report.md
└── images/
    ├── convergence.png
    ├── error_comparison.png
    ├── joint_axis_changes.png
    └── urdf_transform_changes.png
```

## 8. 真实机器人数据采集流程

### 8.1 采集前检查

每次采集前记录：

- 机器人序列号和 URDF 版本；
- 相机、镜头及标定板编号；
- 相机内参和外参版本；
- 末端工具及负载；
- 环境温度和机器人预热时间；
- 支撑方式；
- 关节零位状态；
- 数据采集软件提交版本。

### 8.2 单姿态采集时序

```text
发送目标关节姿态
        ↓
低速运动并完成碰撞监控
        ↓
到位后等待机械振动衰减
        ↓
读取实际编码器关节角，而非命令角
        ↓
连续采集 10～30 帧视觉/动捕数据
        ↓
检测标定板并计算质量指标
        ↓
剔除异常帧并进行稳健平均
        ↓
保存原始数据、转换后位姿和时间戳
        ↓
进入下一个姿态
```

关节角和视觉测量必须对应同一个静止状态。若机器人运动中采集，则需要硬件同步或可靠的时间插值，并额外建模运动模糊和柔性动态误差。

### 8.3 单样本质量检查

出现以下情况时拒绝样本：

- 标定板角点数量不足；
- PnP 重投影误差超过预设阈值；
- 标定板接近图像边缘或严重倾斜；
- 相机曝光异常或运动模糊；
- 动捕标记遮挡或刚体拟合残差过大；
- 机器人仍在运动；
- 两类时间戳差值超限；
- 关节状态、视觉位姿或变换矩阵包含 NaN/Inf；
- 旋转矩阵不合法；
- 机器人发生碰撞、打滑或支撑状态改变。

### 8.4 数据预处理

1. 按时间戳匹配关节角和测量数据；
2. 将单位统一为米和弧度；
3. 把原始观测转换为 `Base_T_EE`；
4. 检查全部变换方向；
5. 计算静态帧内方差和检测质量；
6. 使用稳健方法平均平移和旋转；
7. 剔除明显离群点，但保留剔除日志；
8. 固定随机种子划分标定集和验证集；
9. 保存处理脚本版本和配置。

## 9. 运行实际标定

```python
import roboticstoolbox as rtb

from robotkinecal import SerialRobotKineCal
```

## 10. 实际数据验证流程

### 10.1 独立验证集

分别计算验证集上名义模型和标定模型的：

- 平均、最大和 RMS 位置误差；
- 平均、最大和 RMS 姿态误差；
- 各工作空间区域误差；
- 不同负载与支撑状态误差；
- 不同运动方向误差。

只有验证集误差稳定改善，才说明标定具有实际价值。训练集误差下降但验证集恶化通常意味着过拟合、外参错误或参数不可辨识。

### 10.2 参数合理性

检查：

- 每个旋转轴方向范数是否接近 1；
- 关节轴位置修正是否符合制造和装配公差；
- URDF 局部平移和旋转修正是否存在异常跳变；
- 共享结构在不同分链标定中是否得到相近修正；
- 是否出现某个关节承担大部分全局坐标误差；
- 标定结果是否对少量样本或单一工作区域高度敏感。

真实机器人出现厘米级结构修正时，应优先检查外参、单位、变换方向和时间同步，而不是立即写入 URDF。

### 10.3 重复性验证

建议至少独立采集 3 批数据：

```text
批次 A：求解
批次 B：验证
批次 C：不同时间、重新上电或重新安装后的重复性验证
```

如果各批次估计参数差异显著，说明模型中可能混入柔性、回差、温漂或测量系统漂移。

### 11.2 上线前准备

- 保存名义 URDF、标定 URDF 和参数差异；
- 在仿真中重新检查碰撞模型和末端位姿；
- 检查标定后的关节坐标系不会破坏 mesh、惯量或传感器 frame；
- 使用低速、小范围动作进行实机验证；
- 逐步扩大工作空间和速度；
- 对 MoveIt、控制器和状态估计器执行回归测试。

### 11.3 回滚策略

至少保留：

```text
nominal/robot.urdf
calibrated/robot.urdf
calibration/result.json 或 npz
calibration/report.md
calibration/images/
calibration/dataset_version.txt
```

出现碰撞风险、验证误差恶化或状态估计异常时，应立即恢复名义模型。
