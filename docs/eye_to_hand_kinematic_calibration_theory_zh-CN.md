# 眼在手外数据用于手眼标定与运动学标定：理论与实践汇总

本文档说明固定外部相机观测末端目标的数据，为什么既可以用于手眼标定，也可以直接用于运动学标定；同时明确“复合模型标定”和“机器人本体标定”的数学差异、可辨识性边界以及工程使用方法。

## 1. 场景定义

典型眼在手外系统：

```text
固定相机 Camera
       │
       │ 观测 Camera_T_Target(q)
       ▼
末端目标 Target（Board / Marker / Tracker）
       │ 固定刚性连接 EE_T_Target
       ▼
机器人末端 EE
       │
       ▼
机器人关节链 q
       │
       ▼
机器人基座 Base
```

每个姿态采集：

```text
qᵢ                       实际编码器关节角
Camera_T_Targetᵢ         相机检测的目标完整 SE(3) 位姿
```

假设：

- Camera 在整批采集中相对 Base 固定；
- Target 相对 EE 刚性固定；
- 关节角与图像时间同步；
- 相机内参和 Target 位姿检测有效；
- 所有变换均采用 `A_T_B = B 在 A 中的位姿`。

## 2. 基本变换方程

定义：

```text
X = Camera_T_Base
Y = EE_T_Target
F(q, θ) = Base_T_EE(q, θ)
Zᵢ = Camera_T_Targetᵢ
```

则每条观测满足：

```text
Zᵢ = X · F(qᵢ, θ) · Y
```

其中：

- `X` 是眼在手外相机与机器人 Base 之间的固定外参；
- `Y` 是 Target 相对机器人末端的固定安装外参；
- `θ` 是机器人运动学参数；
- `Zᵢ` 是视觉系统直接给出的观测。

这个方程是整件事情的核心。

## 3. POE 运动学表示

串联旋转关节的 Base→EE 正运动学可写为：

```text
F(q, θ)
= exp(S₁ q₁)
  exp(S₂ q₂)
  ...
  exp(Sₙ qₙ)
  M
```

其中：

- `Sᵢ` 是表达在 Base 坐标系中的空间螺旋轴；
- `M` 是零关节角时的 `Base_T_EE`；
- 当前仓库使用每个旋转关节 4 个独立参数修正螺旋轴，并使用 6 个参数修正末端零位姿态。

代入眼在手外观测：

```text
Camera_T_Target(q)
= X
  · exp(S₁ q₁)
  · ...
  · exp(Sₙ qₙ)
  · M
  · Y
```

## 4. 为什么可以不做手眼标定而直接求复合运动学

利用刚体变换与矩阵指数的关系：

```text
X · exp(S q) · X⁻¹ = exp(Ad_X S · q)
```

其中 `Ad_X` 是 `X` 的伴随矩阵。

在连乘中插入 `X⁻¹X`：

```text
X · exp(S₁q₁) · ... · exp(Sₙqₙ) · M · Y

= exp(Ad_X S₁ q₁)
  · ...
  · exp(Ad_X Sₙ qₙ)
  · X · M · Y
```

定义：

```text
Sᶜᵢ = Ad_X Sᵢ
Mᶜᵗ = X · M · Y
```

于是：

```text
Camera_T_Target(q)
= exp(Sᶜ₁ q₁)
  · ...
  · exp(Sᶜₙ qₙ)
  · Mᶜᵗ
```

这仍然是一个标准 POE 模型。因此：

> 如果只需要建立 `q → Camera_T_Target` 的准确映射，可以直接把 `Camera_T_Target` 作为完整位姿观测输入当前仓库，不需要提前单独知道 `Camera_T_Base` 或 `EE_T_Target`。

此时求出的含义是：

```text
关节轴：表达在 Camera 坐标系
末端零位姿态：Camera_T_Target(q=0)
```

而不是原始的：

```text
关节轴：表达在 Base 坐标系
末端零位姿态：Base_T_EE(q=0)
```

## 5. 固定末端 Target 变换如何影响结果

如果 Base 坐标系不变，只把末端观测统一右乘固定变换：

```text
Base_T_Target(q) = Base_T_EE(q) · EE_T_Target
```

则：

```text
S_target,i = S_ee,i
M_target = M_ee · EE_T_Target
```

因此：

- 固定 Target 偏移不会改变关节螺旋轴的理论值；
- 固定 Target 偏移进入末端零位姿态；
- Board、Marker、Tracker 和工具 TCP 都可以作为标定终端；
- 前提是它们相对 EE 严格固定。

仓库中的数值回归示例：

```bash
python Examples/FixedTargetFrameComparison.py
```

当前示例对全部观测右乘约 9 cm、十几度的固定目标变换，结果为：

```text
原始 EE 求解：converged
Target 求解：converged
最大关节螺旋轴差异：约 1.62e-9
末端零位姿态关系误差：约 1.61e-10
```

数值结果与理论关系一致。

## 6. 固定相机 Base 变换如何影响结果

如果末端 Target 不变，但观测从 Base 坐标系转换到 Camera 坐标系：

```text
Camera_T_Target = Camera_T_Base · Base_T_Target
```

则每个关节轴发生伴随变换：

```text
S_camera,i = Ad(Camera_T_Base) · S_base,i
```

末端零位姿态变为：

```text
M_camera,target
= Camera_T_Base · M_base,ee · EE_T_Target
```

因此两个坐标系中的螺旋轴数值不同，但它们描述的是同一物理运动链，只是表达坐标系不同。

仓库自动测试已验证：

- `Camera_T_Target` 可以直接收敛；
- 求得的关节轴与 `Ad(Camera_T_Base) · S_base` 一致；
- 末端零位姿态与 `Camera_T_Base · M · EE_T_Target` 一致。

## 7. 两种标定模式

### 7.1 模式 A：Camera→Target 复合标定

输入：

```text
qᵢ
Camera_T_Targetᵢ
```

不要求提前知道：

```text
Camera_T_Base
EE_T_Target
```

输出：

```text
q → Camera_T_Target
```

适合：

- 固定相机下的目标位姿预测；
- 视觉伺服；
- 机器人预测与视觉观测一致性检查；
- 固定工位中的 Target/TCP 定位；
- 手眼采集数据的快速质量检查；
- 相机和 Target 长期保持相同安装的任务。

限制：

- 无法分别获得 `Camera_T_Base`；
- 无法分别获得 `EE_T_Target`；
- 螺旋轴不在机器人 Base 坐标系；
- 末端语义为 Target，不是原始 EE；
- 不能直接回写原机器人 URDF；
- 相机或 Target 重新安装后模型失效。

代码：

```python
cal = SerialRobotKineCal(
    robot_model,
    ee_name="panda_link8",
)
cal.set_observations(
    joint_positions,
    camera_T_target_poses,
)
result = cal.solve()
```

虽然 API 中仍传入 `ee_name`，此时标定结果的终端物理语义实际是 Target。项目文档必须明确记录这一点。

### 7.2 模式 B：机器人本体 Base→EE 标定

输入前先转换：

```text
Base_T_EE
= Base_T_Camera
  · Camera_T_Target
  · inverse(EE_T_Target)
```

注意本文采用 `X = Camera_T_Base`，而工程中通常保存的是 `Base_T_Camera = X⁻¹`。

输入：

```text
qᵢ
Base_T_EEᵢ
```

输出：

```text
q → Base_T_EE
```

适合：

- 恢复机器人 Base 坐标系下的运动学；
- 比较机器人本体装配误差；
- 在不同相机和工作站之间复用结果；
- 生成候选 URDF 参数；
- 无视觉系统时继续使用标定模型。

要求：

- 已知并验证 `Base_T_Camera`；
- 已知并验证 `EE_T_Target`；
- 外参误差小于目标运动学精度；
- 使用独立验证集确认结果。

代码：

```python
base_T_ee_poses = [
    base_T_camera
    @ camera_T_target
    @ ee_T_target.inv()
    for camera_T_target in camera_T_target_poses
]

cal.set_observations(joint_positions, base_T_ee_poses)
result = cal.solve()
```

## 8. 为什么复合标定不能自动分离手眼和机器人误差

观测只约束：

```text
Zᵢ = X · F(qᵢ, θ) · Y
```

如果 `X`、`Y` 和 `θ` 全部未知，仅凭这类观测一般存在规范自由度和参数耦合。

### 8.1 左侧坐标系规范自由度

对任意固定刚体变换 `G`，可同时改变：

```text
X' = X · G⁻¹
F'(q) = G · F(q)
```

而保持：

```text
X' · F'(q) = X · F(q)
```

因此仅凭 `Camera_T_Target` 无法知道“相机外参错了”还是“整套机器人模型换了一个表达基坐标系”。

### 8.2 右侧终端耦合

`M` 和 `Y` 总是以乘积形式出现：

```text
M · Y
```

因此只观察 Target 时，无法唯一分离 EE 零位终端变换与 Target 安装外参。

### 8.3 训练误差不代表物理参数正确

复合模型可以具有很低的拟合误差，但这只证明：

```text
q → Camera_T_Target
```

拟合正确，并不能证明：

```text
Camera_T_Base 正确
EE_T_Target 正确
Base 坐标系中的每个机器人几何参数正确
```

## 9. 与传统手眼标定的关系

眼在手外手眼标定通常使用多组机器人末端运动和相机目标运动，估计相机与机器人之间的固定变换。它的重点是固定外参。

运动学标定则估计：

- 关节轴位置；
- 关节轴方向；
- 零位末端姿态；
- 可能还包括关节零偏或其他扩展参数。

同一批数据可以支持两个任务：

```text
qᵢ + Camera_T_Targetᵢ
          │
          ├── 传统手眼标定
          │       ↓
          │   Base_T_Camera / EE_T_Target
          │
          ├── 直接复合运动学标定
          │       ↓
          │   q → Camera_T_Target
          │
          └── 外参转换后本体运动学标定
                  ↓
              q → Base_T_EE
```

三者不是互斥关系，而是对同一数据的不同参数化和使用目标。

## 10. 推荐的双路线工程流程

### 路线 1：复合模型预检

```text
采集 q + Camera_T_Target
        ↓
直接输入 robotkinecal
        ↓
检查收敛、矩阵秩、条件数、验证残差
```

用途：快速检查以下问题：

- 时间同步错误；
- Target 检测离群；
- 标定板或相机松动；
- 关节顺序错误；
- 姿态多样性不足；
- 相机空间预测是否一致。

如果复合模型都不能稳定拟合，通常不应继续做外参分离或 URDF 更新。

### 路线 2：机器人本体标定

```text
使用同一批数据完成/复核手眼外参
        ↓
获取 Base_T_Camera 和 EE_T_Target
        ↓
转换 Camera_T_Target → Base_T_EE
        ↓
运行 robotkinecal 本体标定
        ↓
独立验证
        ↓
谨慎生成候选 URDF
```

推荐最终同时保存：

- Camera→Target 复合模型；
- Base→EE 本体模型；
- 两套模型在各自坐标系下的验证误差；
- 手眼和 Target 外参；
- 数据集和版本信息。

## 11. 数据采集要求

### 11.1 数据格式兼容不等于数据质量足够

传统手眼标定常使用约 15～30 个姿态。运动学标定参数更多，但仓库并不硬性要求上百个样本。对于 `n` 个旋转关节，完整位姿和仅位置观测的计数下限分别为 `ceil((4n + 6) / 6)` 和 `ceil((4n + 3) / 3)`；7 自由度时分别是 6 和 11。该下限只表示约束数量可能足够，不代表数据满秩或结果可靠。

建议：

| 用途/测量条件 | 建议标定姿态数 |
|---|---:|
| 无噪声仿真或公式检查 | 8～15 |
| 算法与数据接口调试 | 10～20 |
| 高质量动捕或激光跟踪 | 20～40 |
| 稳定工业视觉/多相机 | 30～60 |
| 常规 AprilTag/棋盘格视觉 | 50～100 |
| 高噪声、遮挡明显的视觉 | 80～150 |
| 独立验证 | 15～30；高噪声时 20～40 |

已有 20～40 组且姿态分布良好的眼在手外手眼数据，可能已经足够完成复合 `q → Camera_T_Target` 模型的首次求解。是否需要补采应由回归矩阵秩、条件数、独立验证误差和分批求解的参数稳定性决定，而不是仅由总数量决定。仅位置观测通常需要更多数据：高质量测量约 30～60，常规视觉约 60～120，高噪声时约 100～200。

样本少时可能出现两个阶段。第一阶段是不可辨识：样本低于计数下限，或者 Camera、Target 和各关节的运动变化不能激励全部参数，使回归矩阵秩亏，此时不存在唯一的完整参数解。第二阶段是弱可辨识：回归矩阵刚好满秩，求解器能够收敛，但最小奇异值很小、条件数较大，测量噪声会被明显放大；不同数据子集可能产生差异很大的参数。

样本增加且姿态互补时，会为最小二乘提供冗余并降低随机噪声影响。独立同分布噪声的理想情况下，估计误差约按 `1 / sqrt(N)` 下降。但视觉连续帧通常具有相关性，固定的手眼外参偏差、相机内参误差、Target 尺寸误差和同步偏差属于系统误差，因此不能通过堆积相似帧消除。一次姿态下连续采集多帧，可以用于平均该姿态的观测和评估静态重复性；运动学辨识所需的数据量仍应按不同关节配置的数量计算。

### 11.2 姿态激励

运动学标定需要：

- 每个关节有明显正负运动；
- 相邻关节不要始终同步；
- 覆盖近、中、远工作空间；
- Target 具有多个明显方向；
- 覆盖相机图像不同位置和深度；
- 避免奇异位形；
- 标定集和验证集独立。

只有平移、Target 始终正对相机或所有关节联动的手眼数据，可能足够估计粗略外参，但不一定足够辨识全部运动学参数。

### 11.3 同步与刚性

必须保证：

- `qᵢ` 来自实际编码器而不是命令角；
- `qᵢ` 与 `Camera_T_Targetᵢ` 对应同一静止时刻；
- Camera 在整批数据内不移动；
- Target 相对 EE 不移动；
- 相机内参、图像分辨率和检测算法配置不变。

如果 Camera 或 Target 在批次中移动，固定变换假设被破坏，不能把变化前后的数据直接混合。

## 12. 误差来源与解释

### 12.1 复合模型可能吸收的误差

- 相机外参误差；
- Target 安装外参；
- 机器人关节几何误差；
- 关节编码器零偏；
- 相机内参和 PnP 系统误差；
- 时间同步误差的系统性部分。

### 12.2 不能由刚性模型稳定吸收的误差

- 相机或 Target 松动；
- 机械柔性随姿态变化；
- 负载变化；
- 齿轮回差和运动方向效应；
- 温度漂移；
- 运动模糊和随机离群点。

这些误差通常表现为验证残差、批次间参数变化或某些工作空间区域误差恶化。

## 13. URDF 使用边界

### 13.1 可以考虑回写原 URDF

仅当：

- 观测已转换为 `Base_T_EE`；
- Base 和 EE 的物理定义与 URDF 一致；
- 外参经过独立验证；
- 独立验证集显著改善；
- 参数修正符合机械公差；
- 仿真和低速实机回归通过。

### 13.2 不得直接回写原 URDF

当输入为：

```text
Camera_T_Target
```

时，输出是 Camera→Target 复合模型。直接把其 XYZ/RPY 写入原 URDF 会把：

```text
Camera_T_Base
EE_T_Target
```

错误解释为机器人连杆几何。

如果 Target 是实际需要的工具坐标系，应显式建模：

```text
robot_ee
   └── target_link（fixed joint）
```

并将 `EE_T_Target` 放在固定 joint 中。

## 14. 验证指标

无论使用哪种模式，都应在独立验证集上比较：

- 平均、最大和 RMS 位置误差；
- 平均、最大和 RMS 姿态误差；
- 回归矩阵秩；
- 条件数和奇异值；
- 不同工作空间区域误差；
- 不同批次的参数重复性。

模式 A 比较：

```text
预测 Camera_T_Target vs. 观测 Camera_T_Target
```

模式 B 比较：

```text
预测 Base_T_EE vs. 外参转换后的 Base_T_EE
```

两种验证结果回答的问题不同，不能混为同一个精度结论。

## 15. 常见问题

### Q1：手眼采集数据可以直接给本仓库吗？

可以。使用 `qᵢ + Camera_T_Targetᵢ` 可以直接标定 Camera→Target 复合模型。

### Q2：这样是否等于完成了手眼标定？

不等于。它获得整体映射，但不单独输出 `Camera_T_Base`。

### Q3：是否还需要知道 `EE_T_Target`？

复合模型不需要；恢复原 EE 或更新原 URDF 时需要。

### Q4：相机移动后还能使用复合模型吗？

不能。相机移动会改变全部 Camera 坐标系下的关节轴和末端零位姿态。

### Q5：标定板重新安装后还能使用吗？

不能直接使用。新的 `EE_T_Target` 会改变末端零位姿态。

### Q6：为什么复合模型训练误差很低，仍不能更新 URDF？

因为低误差只证明 `q → Camera_T_Target` 映射正确，没有证明相机外参、Target 外参和机器人本体参数分别正确。

### Q7：什么情况下优先使用复合模型？

固定工位、固定相机、固定工具，并且任务输出本来就在 Camera/Target 坐标系时。

### Q8：什么情况下必须做外参分离？

需要更新机器人本体、跨相机复用、在 Base 坐标系控制或移除 Target 后继续使用时。

## 16. 最终结论

1. 眼在手外手眼标定采集的 `q + Camera_T_Target` 数据，与当前仓库的完整位姿观测格式兼容。
2. 不预先做手眼标定，也能得到准确的 Camera→Target 复合 POE 模型。
3. 固定相机变换通过伴随映射改变关节轴的表达坐标系；固定 Target 变换进入末端零位姿态。
4. 复合模型不能唯一分离相机外参、Target 外参和机器人本体几何。
5. 要恢复 Base→EE 物理模型或更新原 URDF，仍需已知外参并转换观测。
6. 同一批数据最适合走“双路线”：先做复合模型预检，再完成外参转换后的本体标定。
